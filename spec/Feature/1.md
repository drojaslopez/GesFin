# Solicitud de Cambio: Implementación de Patrón CQRS

## Descripción

Modificar la estructura de la aplicación para separar las operaciones de lectura (consultas) de las de modificación (comandos), alineando el backend con Domain-Driven Design y Arquitectura Hexagonal.

## Estructura de Paquetes

1. **Comandos (Writing Model):**

   - Agrupar controladores, casos de uso y repositorios dedicados exclusivamente a la creación y modificación de datos (ej. `CreateGoalCommand`, `RecordContributionCommand`).
2. **Consultas (Reading Model):**

   - Agrupar controladores, servicios y DTOs de lectura enfocados en la obtención de datos para la interfaz familiar (ej. `GetFamilyProgressQuery`, `GetGoalDetailsQuery`).

## Instrucciones para el Agente IA

1. Reestructurar los casos de uso existentes en el paquete `application` dividiéndolos en sub-paquetes `commands` y `queries`.
2. Adaptar los controladores REST para invocar explícitamente a los comandos o queries correspondientes según la operación HTTP.
3. Asegurar que las consultas omitan la lógica de negocio y mapeen directamente los datos a Read DTOs.
